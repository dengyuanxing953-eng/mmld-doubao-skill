# 浏览器发布经验

2026-09-28经验快照，适用于未来页面诊断，不保证选择器长期有效。使用当前运行环境允许的浏览器API；不恢复旧Cookie，不读浏览器私有存储，不用注入脚本替代发布按钮。

## 控制与等待

- 优先页面语义定位和当前DOM/可访问树。点击只触发悬停、面板未开或状态不变时，先观察，再尝试有依据的键盘激活或可见控件；不重复盲点。
- 避免在同一长调用里叠加大量高延迟动作导致会话重置。小批操作后立即回读，操作超时保留“结果未知”。
- 文件上传经file chooser。先打开图片面板，再找到真正的“本地上传”按钮，才注册filechooser等待；工具栏“图片”按钮可能只打开面板。
- chooser等待必须捕获拒绝，超时不得留下未处理Promise导致运行环境重置。设置能覆盖工具往返的有限超时；没有事件就重新观察，不循环扩长等待。
- 优先可见关联label/上传按钮，隐藏input点击失败不需要改网页样式。多文件先核实该控件支持多选。
- 截图坐标仅根据当前图像的真实尺寸；界面缩放、滚动或换标签后重新观察。优先语义定位，不依赖旧坐标。

## 内容完整性

文本fill可能留下全选，也可能不触发编辑器的保存事件。插图前明确折叠选区并定位；插图后再检查文字长度、开头、结尾与图片数。不能看见图片就假定正文还在。

带iframe或旧版富文本编辑器（例如UEditor）中，屏幕看得到文本不代表已持久化：
1. 使用普通粘贴路径，必要时切入正确iframe；
2. 保存后回读或重新打开同一草稿；
3. 如果正文丢失，恢复原稿并采用原生输入事件，再核验；
4. 不调用页面内部编辑器状态或网络接口来绕过正常控件。

空白占位符、可选图片说明和图片懒加载不能算正文/上传失败。检查正文图片节点、实际载入状态与滚动后的呈现，避免把模板1像素占位图误判为最终图。

## 当前平台经验

| 平台 | 关键检查 |
|---|---|
| 头条 | 图卡上传可能替换仍被选中的全文；校验恢复正文。三图封面会自动裁剪，按当前比例做封面。发布后列表可能有缓存，刷新一次查标题、时间、URL与“已发布” |
| 知乎 | “图片”通常先开面板，再选“本地图片上传”，上传后还要“插入图片”。封面单独上传；文章发布成功弹窗不等于已同步想法/圈子，未要求就不追加分享 |
| 百家号 | 标题编辑器与iframe正文不同；预览可能有正文而重开后为空。先验证保存，再发布；“提交成功，正在审核中”与“已发布”分开；关闭未请求的自动播客 |
| 什么值得买 | 正文图片、长封面、方封面不同；图卡不能代替封面校验。利益相关与AI声明要按真实情况选择。可访问树checked缺失时，可见选中样式与截图可作为佐证；不能用DOM改值制造选中 |
| 抖音 | 确認当前账号、图文/文章入口和适用限制；娱乐个人号不自动升级为项目账号 |
| 小红书/B站/搜狐/腾讯内容平台 | 先确认当前登录与发布权限；已有本地适配稿不能当线上草稿；登录页不证明永久封禁 |

## 重试与去重

同一内容版本按平台+账号+内容ID或文件哈希记账。提交后超时先看后台、草稿和公开页：
- 已发布：补回执，停止重发；
- 审核中：等待或查询一次状态，不重复提交；
- 草稿：核对完整内容后再决定是否重试；
- 未知：停止依赖项、标记未知并保留可继续入口。
可做一次针对已定位原因的修复，再验证；仍受相同限制时不要耗尽时间反复点击，报告具体阻塞。
