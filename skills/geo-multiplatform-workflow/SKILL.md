# GEO 多平台发布

## 输入与范围

先判断用户要方案、稿件、草稿提交还是公开发布。复用当前会话的有效授权与已有事实，不为日常编辑选择重复索要批准。明确要求发布可授权按目标执行；新发现的无关个人账号、范围外目的或敏感内容需要单独澄清。工具强制确认/用户接管要求优先。

只提取完成内容必需的事实。公司证件、订单、私聊、学生信息和凭证不进入通用发布包。没有业务事实时可交付清楚标记的通用方法示例，但不能冒充品牌课例、真实评价或执行效果。

## 执行

1. 查看近期已发布标题和正文，选择有信息增量的主题。用户只问主题就回答主题；用户同时要求发布则继续执行，不能只交计划。
2. 核验平台能力与当前账号归属。开放图文、认证企业资料、课程商品、投诉、招聘分别处理；高频AI来源不是开放文章权限。抖音可用图文时直接用图文，不强制转视频。
3. 从同一事实卡生成适合平台的版本，实质改变受众、问题、证据、结构或呈现；不机械要求一定七个平台、三张图或固定篇幅。用户明确要统一公告时保留一致正文与日期。
4. 图文稿包含可阅读图片和完整文字。图卡可解释流程、例题或判断标准，不伪造课堂/学员/证件。数学计算等可确定内容做实际核对。图片中关键结论也保留在正文。
5. 按平台设置AI标识、利益关系、封面。独立平台版本不随意声明独家首发；未请求的自动生成音频、交叉转发或付费加热不默认开启。
6. 按 [浏览器操作经验](references/browser-publishing.md) 处理编辑器。公开发布前回读标题、完整正文、图片、封面、声明、账号。保留旧草稿，新建本轮版本。
7. 提交后查后台，再查真实公开页面。执行 [回执契约](references/receipts.md)；超时或不确定时先查是否成功，不能直接再次提交。
8. 有登录/验证码/权限阻塞时，保留稿图与状态，继续独立渠道。用户拒绝某账号或尚未回复的必要确认，不因等候超时自行视为授权。
9. 报告逐平台结果与链接：公开发布、审核中、草稿、未发分别计数。保存含状态的证据，不把工具点击成功作为网站成功。

## 验证工具

~~~sh
python scripts/validate_receipts.py receipts.json
~~~

支持简单JSON数组，不强迫小任务凑齐十二份模板。验证器检查证据结构和状态，不证明网页真实可读。索引与AI观察需另测，不能由validator成功推导。

## 按需后续

先回读已有内容，再决定新增频次。T+48小时、T+7/T+14可作初始检查点，按真实发布时间计算，不承诺抓取周期。需要引用统计可调用geo-automonitor；未安装时直接保留观测原件和未知项。

公开内容涉及受限制行业时核验实际规则，例如中小学培训广告不能通过“经验分享”更名规避。真实不利事实与真实未结售后问题不能被写成不存在。
