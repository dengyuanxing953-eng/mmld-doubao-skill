# 豆包变化与声誉信息应对

适用：用户反馈界面、检索、规则频繁变化，或要求减少错误负面概括。目标是提高事实准确性、售后可办理性与可核验性；不承诺让真实不利信息消失。

1. 分清UI变化、登录/验证码、索引缺失、来源波动、内容审核与正式规则变化。协议更新日期本身不能证明引用算法已改变。
2. 先处理错主体、错年份、课程版本混用、同一投诉跨域重复、平台汇总误归商家、处理状态误读。投诉主张、商家回复、平台标记、到账/结案事实分开。
3. 修复有权维护的源页面；没有编辑权限就生成字段修改稿和证据，不冒充已改。没有私密订单可核验就保留个案未知，不向企业索取全部客户档案。
4. 内容以自然问题和新增证据驱动。两篇有事实增量的长文可形成骨架，是否加图文取决于素材和渠道；不给所有行业规定固定日更或48小时间隔。
5. 可采用T+0回读、T+48小时索引、T+7/T+14跨日AI观察，T+28复盘。这是起始排期，不是官方抓取时间或见效承诺。临时故障停止依赖项后继续独立工作。
6. 保留少量跨引擎对照。普通查询、给定URL测试、API检索、消费者自然回答分别记录；不把“喂链接后会引用”当自然引用。
7. 纠错反馈附准确原文、原网页、日期、主体与期望修正范围；不批量举报真实差评。正式权利通知需权利人材料，不能用普通反馈替代，也不擅自发邮件。
8. 当维护单引擎工具的成本持续高于可验证收益，降低专用脚本和铺稿投入，保留适量观察，把工作转到可长期维护的源内容。阈值由预算与任务确定，不硬编码某个百分比。
